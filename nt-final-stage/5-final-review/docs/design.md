# v0.3 实现说明

沿用 v0.2 的 CLI/API 适配器、预留调用预算、SQLite 记录、任务锁和模型进程取消。

新增 protocol.py：模型响应分为元数据与原样正文，数学内容不经过模型手写 JSON 的解码。元数据只含控制信息；输出原文、解析后的 body.md、完整结果均可追溯。

新增 workflow.py：分别审查两个分支，按 verdict 定向修订。结果由程序装配，避免未经审查的汇总改写。每个修订阶段有稳定键，恢复时不会重复调用已完成阶段。

新增 findings.py：全量校验 JSONL、创建并冻结子任务清单、每条独立预算与恢复；既保留流程状态，也保留五类结论状态。

新增 execution.py：Docker-only 标准库检查脚本，实际进程输出捕获、镜像 ID 记录、无外部网络、无主机挂载与资源限制。环境不可用时暂停，保留已付费分析。脚本运行成功本身不认证数学结论。

岗位超时由 timeouts 配置，分析／修订默认 1200 秒。旧任务的缓存协议不兼容，要求用旧版本完成。


# v0.4 编辑循环

新增 editloop.py，`run` / `batch` 不变。参照 ATHENA 的“提议者—批评者”结构：规划对应 Strategist，两位分析者是并行提议者，独立审查对应 Critic，调度器预检对应 Inspector（在执行前核对补丁与计划、能否编译），备份仓库与报告对应 Storage。

- 单元切分：在 `\begin{theorem|definition|…}` 与 `\section` / `\subsection` 前切开，覆盖整个正文；没有实质文字的片段（标题、分页）并入下一个单元。
- 提示：可编辑单元原样嵌入（不经 JSON 转义），模型才能逐字复制 OLD。只读资料包括导言区宏定义、Notation 一节、本单元引用的结论全文、全文中引用本单元 label 的位置。
- 修改块：`<<<COOP_EDIT id>>> / <<<COOP_OLD>>> / <<<COOP_NEW>>> / <<<COOP_EDIT_END>>>`。OLD 先逐字匹配，失败再忽略空白匹配（只容忍空白差异，内容必须一致），都必须唯一。
- 一致性判断按“应用后的结果（忽略空白）”比较，两份盲答效果相同则跳过交换。
- 写入顺序：检查源文件 == 备份 HEAD → 记录 applying（写前/写后哈希）→ 原子替换 → 备份提交 → 标记 applied。中断后按哈希判断写没写成，绝不重复写入。
- 断点续跑：模型调用按 (单元任务, 阶段键) 缓存；预检、每轮记录、写入状态存 SQLite。续跑时从第 1 轮重放，已完成的步骤全部取缓存。
- Store.call：从 stage 中拆出的通用调用，接受惰性 prompt（只在缓存未命中时构造）、issue_filter 和输出校验；校验失败的调用记为失败、不缓存。


# v0.4.1 网页仲裁

对应 ATHENA 中 Critic 驳回后升级给更强求解者的做法；这里的强求解者是网页版模型，通过人工复制粘贴接入，调度器不访问网页。

- 触发：普通轮次没有收敛，且（交换意见后两方效果仍不同 / 审查打回 / 来回修改）。预检失败不触发。`after_rounds` 控制从第几轮起升级，`max_per_unit` 控制次数。
- 停放：单元状态 `awaiting_web`，`edit_web` 表记一条 (单元, 仲裁轮号, waiting)。其余单元继续；运行结束后导出批次。
- 批次：`web/batch-NN.md`，按单元数和字符数分批。导言区宏定义与背景约定每批只放一次；每个单元带未收敛原因、只读资料、当前原文、自动循环历史。回复格式是 `<<<UNIT id>>>` 包住一个普通 COOP 帧。
- 导入：只认标记行，忽略代码块围栏和闲聊，可多次追加。逐单元用与模型调用相同的解析器校验（kind 容错，check 一律关闭）；失败的单元留在 waiting。根据「收到」行区分“粘贴被截断”和“回复没写完”。拒绝导入批次文件本身。
- 重放：resume 时从第 1 轮按缓存重放到触发点，读到已导入的回复就进入仲裁轮：补丁 → 预检 → 审查（看仲裁理由，不看分析者讨论）→ 写入 → 两位分析者确认。仲裁者的 done 代替规划者的票。没收敛就回到普通轮次；仲裁轮不占 `max_rounds`。
- 旧会话：冻结的配置里没有 `edit.web` 时按关闭处理。
