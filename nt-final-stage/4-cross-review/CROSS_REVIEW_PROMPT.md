# 交叉审查：三方合并的结果（第 4 步）

你是一位独立的审查者，负责检查一次三方合并做得对不对。合并的结果是一份英文 LaTeX 初等数论讲义的最终稿（约 13,500 行、约 200 页、三百多个定理、一百多个定义）。合并是另一个模型做的，你没有参与，也看不到它的思考过程；不要因为它是强模型、或者它的说明写得自信，就默认它对。

## 你收到的材料

紧跟在这段说明后面的是下面几份文件。每份都用两行标记包住：`===== 文件：名字 … =====` 开头，`===== 文件结束：名字 =====` 结尾。文件也可能以附件形式给你，文件名相同。

| 文件 | 是什么 |
|---|---|
| `baseline.tex` | 共同祖先。下面两条分支都从它分出来 |
| `branch1.tex` | 作者一侧：经过多轮前沿模型数学审查、Muse Wonder 一轮、作者的手工修改。它新增过带编号的环境，后面的 label 顺延了（例如 baseline 的 `def:5.7.1` 在 branch1 里是 `def:5.7.2`） |
| `branch2.tex` | 27B 模型一侧：全文英文润色，以及经复核后采用的 DeepSeek 审计表 LOW 条目修补和引用核查修补。label 与 baseline 相同 |
| `final.tex` | 合并的结果，你要审查的对象。label 和带编号的环境应当与 branch1 完全相同 |
| `merge-log.md`（可能有） | 合并模型自己写的说明：每处回滚、冲突处理、新的数学修改、自行优化各一条 |

也可能收到的不是 4 份全文，而是一份**材料包**：只含合并中有风险的单元，每个单元给出 final 的全文和三段差异（baseline→branch1、baseline→branch2、branch1→final），其余单元只列出 id 和取自哪边。这时按同样的要求审查材料包里的单元。

合并时，合并模型有这些自主权：可以回滚只有一边做过的修改，可以在冲突处选一边、融合或重写，可以做小幅的数学修正和自行优化。但每一处都必须写进 `merge-log.md`。硬约束是：label 和带编号的环境与 branch1 相同，从 branch2 / baseline 搬来的引用要按 label 对照改成 branch1 的名字，能编译。

## 先确认收到了什么

回复的第一行写：

`收到：baseline.tex（N 行，最后一行「…」）、branch1.tex（…）、branch2.tex（…）、final.tex（…）、merge-log.md（有 / 没有）`

每个文件开头的标记行里写着它的行数和最后一行，请核对。核对不上，说明粘贴被截断，或者附件没有被完整读入，要如实写出来。如果你只能读到附件的一部分（例如只能检索、不能通读），也要直说，并在“覆盖”一项里写清楚实际看过的范围。

## 要查什么（按重要性）

判断一处修改是谁做的、改了什么，永远以 baseline 为参照：final 与 branch1 不同的地方，就是合并留下的痕迹。

1. **合并本身的错误**
   - **丢失修改**：一边有意的修改在 final 里没了，日志里也没有说明理由；
   - **冲突处理不当**：融合时丢掉了某一边的要点，或把两边拼得前后矛盾、重复、语法断裂；
   - **回归**：final 采用了 branch2（或 baseline）的句子，却丢了 branch1 在同一处已经修好的数学问题。这在两边都改过的单元里最容易发生；
   - **引用错误**：搬过来的 `\ref` / `\eqref` 没有按对照改名，结果指向了别的定理或定义；也要留意 4.2、5.7 这些新增过定义的小节；
   - **结构**：label、theorem / definition 环境与 branch1 不一致；内容错放到别的单元；重复的段落。
2. **合并模型自己写的内容**：日志里的“新的数学修改”，以及 final 中与两边都不同的文字。逐条核对它们在数学上是否正确、是否真的必要；核对日志里写的回滚理由是否成立。也要找出改了却没写进日志的地方。
3. **一致性**：合并后全书的记号、术语、写法是否前后一致（同一个对象有没有出现两种写法）。
4. **LaTeX**：明显会编译失败或排版出错的写法。

不在范围内：
- 纯粹的风格偏好；
- 重新审一遍全书的数学（第 5 步会逐单元做多模型数学审查）。

但如果你顺带看到了明确的数学错误，也写下来，类别记为“其他数学疑点”。

篇幅太长、看不完全书时，按这个顺序优先：
1. final 与两边都不同的单元；
2. 两边都改过的单元；
3. 日志里写了回滚的单元；
4. 新增过定义的小节附近的引用；
5. 其余 final 与 branch1 不同的单元。

## 回复格式

先写四行总述：

```
收到：……
覆盖：（实际逐单元核对过的范围，例如“第 1–6 章全部单元；第 7–9 章只看了两边都改过的单元”；没看的要写明）
结论：可以进入第 5 步 / 先修 blocking 问题再进入第 5 步
统计：blocking N，major N，minor N
```

然后每个问题写一个块。标记行单独成行，原样书写：

```
<<<FINDING F1>>>
单元：thm:4.3.1（用 final.tex 里的 label；说明文字单元写所在小节的标题）
类别：丢失修改 / 冲突处理不当 / 回归 / 引用错误 / 结构 / 新数学修改有误 / 回滚不当 / 未记录的修改 / 记号不一致 / LaTeX / 其他数学疑点
严重度：blocking / major / minor
final 原文：（从 final.tex 逐字复制的片段，不超过 3 行，用来定位）
问题：（说清楚错在哪里；数学问题给出理由或反例）
依据：（baseline / branch1 / branch2 中对应的逐字片段，注明出自哪一份）
建议改为：（可选：替换上面“final 原文”的 LaTeX）
<<<END F1>>>
```

- 严重度：
  - **blocking**：数学错误、命题不成立、证明缺口；引用指错对象；label 或编号环境被改动；丢失了 branch1 已经修好的数学问题。
  - **major**：一边有意的修改被无理由地丢掉，或冲突处理明显不如两边任何一边。
  - **minor**：措辞、记号一致性、排版。
- 片段一律逐字复制，包括反斜杠；不要凭记忆改写原文，也不要编造行号。
- 不要输出整份文件或大段全文。
- 你也可能弄错：拿不准的问题照样写，在“问题”里说明哪里拿不准。
- 篇幅不够时，只在两个问题块之间停下，最后一行写“未完：”和接下来要看的范围。我回复“继续”后，从下一个问题接着写，编号接着往下排，不必重复总述。
